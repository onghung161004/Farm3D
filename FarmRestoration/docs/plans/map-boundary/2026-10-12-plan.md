# Implementation Plan: Map boundary

Spec Source: 2026-10-12-spec.md. Owner: current agent. Status: Done.

## 1. Context
PlayerMovement.Move does not constrain positions to the finite farm mesh. Guard both mobile and keyboard movement and recover exceptional falls. No economy/save/NPC changes.

## 2. Constraints
C#, Unity 6000.6.1f1, existing CharacterController. No scene writes or dependencies. One bounded terrain raycast per update; no scene search once terrain is found.

## 3. Conventions
FarmRestoration namespace, PascalCase public APIs, Unity null guards. NUnit EditMode fixtures with DestroyImmediate teardown. Native geometry is exercised directly, not mocked.

## 4. Contracts
PlayerMapBoundary.Configure(MeshCollider): replace terrain and reset safe state. Null disables boundary.
Constrain(Vector3, float): preserve height; clamp XZ to bounds inset max(2 m, radius); missing terrain passes through.
TryRecover(Vector3, out Vector3): track supported point; return recovery position only for below-terrain/deep-void falls. Does not mutate player or inventory.

## 5. Architecture
PlayerMovement -> Constrain proposed displacement -> CharacterController.Move -> gravity -> TryRecover -> cancel fishing, teleport and reset velocities. Bounds come from the actual named terrain collider; this existing terrain is rectangular and axis aligned.

## 6. Artifacts
TASK-001: Scripts/Player/PlayerMapBoundary.cs plus .meta.
TASK-002: Scripts/Player/PlayerMovement.cs integration.
TASK-003: Tests/EditMode/PlayerMapBoundaryTests.cs plus .meta, delivery result here.

## 7. Task graph
Small task executed end to end under user's instruction to implement without repeated questions. Sequence: boundary core -> movement integration -> verification. Alternatives horizontal-layer or multi-sprint process offer no benefit for this localized change. TASK-001 -> TASK-002 -> TASK-003; no delegation or commit.

## 8. Task specifications
TASK-001: use terrain bounds and downwards terrain ray. Outside X/Z -> inset coordinate, preserve Y; supported point -> remembered safe point; below surface by >3 -> safe recovery; missing mesh -> unchanged position and no recovery.
TASK-002: lazily resolve terrain once per second until found. Clamp planar move. On recovery disable/re-enable CharacterController around teleport and zero motion/gravity. Cancel active fishing so controls are not left locked.
TASK-003: test all corners and height, translated bounds, exact margin, null/empty collider, deep fall after valid point, no false recovery above ground and duplicate recovery stability. Compile runtime and run regression suite in isolated Unity project.

## 9. Edge cases
Null/empty mesh, zero horizontal movement, tiny mesh bounds, translated bounds (TASK-001); below-mesh/void fall, no recorded safe point and repeated recovery (TASK-001/002); fishing controls lock during rescue (TASK-002). Non-finite positions are outside this feature scope.

## 10. Risks
Bounds fit rectangular terrain, not arbitrary future irregular islands. Terrain ray excludes props and the bridge; save safe terrain points only, not bridge roofs. Safe return does not reset money/items.

## 11. Verification
NUnit bounds/surface/rescue assertions and existing movement/fishing/cow tests. Manual: walk to four edges on PC/Android, remain inside; force player below terrain and confirm safe return without continued fall. Android requires updated APK; device/rendered validation is not automated here.
