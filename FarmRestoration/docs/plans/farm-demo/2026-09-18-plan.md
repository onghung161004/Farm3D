# 1. Context

**Problem:** The new Unity URP project has only its generated sample scene. It needs a small, coherent 3D farming loop that demonstrates movement, interaction, animation-ready world feedback, and Android-ready rendering without expanding into a full farming simulator.

**Affected Modules:**

- `Assets/Scenes` - playable demo scene and build scene list.
- `Assets/Scripts/Player` - movement and interaction input.
- `Assets/Scripts/Farming` - plot and crop-state rules.
- `Assets/Scripts/UI` - visible tool prompt and harvested-crop count.
- `Assets/Prefabs` and `Assets/Materials` - reusable low-poly placeholders.

**Non-Goals:** NPCs, animals, quests, save data, shops, final art, mobile touch controls, and multiple crop varieties.

---

# 2. Constraints

**Language:** C#
**Architecture:** Unity MonoBehaviour components with small, inspector-configured dependencies; gameplay state is owned by `FarmPlot`.

**Rules:**

- Keep packages already supplied by the Unity 6.6 URP template; add Cinemachine only if the existing camera approach cannot meet the follow-camera acceptance criteria.
- Do not edit files inside `Library/` or generated Unity metadata manually.
- Place all custom assets below `Assets/FarmRestoration/`.
- Preserve a keyboard/editor workflow while selecting APIs compatible with future Android input.

**Performance Budgets:** 60 FPS target on mid-range Android; no allocations in `Update`; fewer than 100 active scene objects in this slice.

---

# 3. Conventions

**Naming:** C# classes and serialized fields use PascalCase/camelCase respectively; files match their public class; enums use singular PascalCase names. Scenes and prefabs use PascalCase.

**Error Handling:** Public setup methods fail fast with `Debug.LogError` and disable only the dependent component when inspector references are absent. Invalid player actions return `false` and do not mutate plot state.

**Logging:** No runtime spam. Log only missing required references or invalid configuration during `Awake`/`OnValidate`.

**Testing:** Unity Test Framework EditMode tests under `Assets/FarmRestoration/Tests/EditMode`. Tests name the subject and expected result, e.g. `FarmPlot_TillWithHoe_ChangesStateToTilled`.

**Task Size:** Keep each task within 200 lines of production code excluding tests; split otherwise.

# 4. Contracts

## Enum: `FarmPlotState`

```text
Untilled | Tilled | Seeded | Watered | Growing | ReadyToHarvest
```

The state starts as `Untilled`; states only progress in the listed order. Harvest returns to `Untilled`.

## Enum: `FarmTool`

```text
Hoe | Seeds | WateringCan | Harvest
```

## Interface: `IInteractable`

```text
bool TryInteract(FarmTool tool)
  - pre: caller is within the configured interaction range
  - post: returns true and applies exactly one valid state transition; returns false without state change otherwise
  - throws: never; missing setup logs an error during initialization instead

string GetInteractionPrompt(FarmTool tool)
  - pre: tool is a defined FarmTool value
  - post: returns a concise action/status prompt suitable for a HUD
```

## `FarmPlot`

```text
CurrentState: FarmPlotState - read-only to other components
TryInteract(tool) -> bool
AdvanceGrowth() -> bool
  - pre: CurrentState is Watered or Growing
  - post: Watered -> Growing; Growing -> ReadyToHarvest; otherwise false/no change
Harvested event -> Action<int>
  - post: fires once with amount 1 only when ReadyToHarvest is harvested
```

## `PlayerToolController`

```text
SelectedTool: FarmTool - current selected tool
SelectTool(index: int) -> void
  - pre: index in [1,4]
  - post: maps 1..4 to Hoe, Seeds, WateringCan, Harvest; out-of-range leaves selection unchanged
TryUseTool() -> bool
  - post: finds the nearest targeted IInteractable in range and forwards SelectedTool; false when none is valid
```

## `InventoryState`

```text
HarvestedCrops: int - starts at 0, never negative
AddCrop(amount: int) -> void
  - pre: amount > 0
  - post: HarvestedCrops increases exactly by amount
```

# 5. Target Architecture

**Components:**

- `PlayerMovement` - reads movement input and drives CharacterController.
- `PlayerToolController` - selects tools and invokes an in-range plot.
- `FarmPlot` - validates state transitions and controls visual child objects.
- `InventoryState` - owns harvested count for this scene.
- `FarmHud` - subscribes to selection, prompt, and inventory changes.
- `FarmDemoBootstrap` - connects inspector-assigned scene objects and configures starting state.

**Interaction Flow:**

```text
Keyboard / future touch input
  -> PlayerMovement.Move() -> CharacterController.Move()
  -> PlayerToolController.SelectTool() / TryUseTool()
    -> FarmPlot.TryInteract(selectedTool) -> state transition + visual update
      -> FarmPlot.Harvested(1) -> InventoryState.AddCrop(1) -> FarmHud.SetCropCount(1)
  <- HUD shows selected tool and valid next action
```

**Key Decisions:**

- Use a finite state machine instead of timers for initial crop growth so the whole loop is repeatable in a short assessment demo.
- Use primitives and URP Lit materials first; imported art is intentionally decoupled from gameplay scripts.
- Keep interaction target-based rather than hard-coding a plot reference so future plots can reuse the same controller.

# 8. Task Specifications

## TASK-001: Create project structure and playable scene shell

**Phase/Sprint:** 1: Explore the farm

**Input:** Generated Unity URP project and `SampleScene.unity`.

**Output:** Asset folders and `FarmDemo.unity`, consumed by TASK-002, TASK-004, and TASK-006.

**Files:** Create folders under `Assets/FarmRestoration/{Scenes,Scripts,Prefabs,Materials,Models,Textures,Animations,Audio,UI,Tests/EditMode}`; create `Scenes/FarmDemo.unity`.

**Responsibilities:** Create a ground plane, directional light, URP-compatible low-poly colour materials, and an empty bootstrap root. Do not hand-edit `.meta` files.

**Acceptance Criteria:**

- [ ] Opening `FarmDemo.unity` shows a lit ground plane and no missing-script warnings.
- [ ] Scene uses only custom files below `Assets/FarmRestoration` plus Unity packages.

## TASK-002: Implement player movement and third-person camera

**Phase/Sprint:** 1: Explore the farm

**Input:** TASK-001 scene shell.

**Output:** A player prefab/object with `PlayerMovement`; consumed by TASK-003 and TASK-006.

**Files:** Create `Scripts/Player/PlayerMovement.cs`; create/update player and camera objects in `FarmDemo.unity`.

**Responsibilities:** Read Input System movement actions (or temporary keyboard actions), normalize diagonal input, move through `CharacterController`, rotate toward movement direction, and follow with a damped camera.

**Acceptance Criteria:**

- [ ] WASD/arrow input -> player moves relative to camera direction.
- [ ] diagonal input -> speed is no greater than configured move speed.
- [ ] no input -> player remains stationary and camera remains stable.

## TASK-003: Implement tool selection and plot targeting

**Phase/Sprint:** 2: Farm one plot

**Input:** TASK-002 player/camera; `IInteractable` from TASK-004.

**Output:** `PlayerToolController`, consumed by TASK-005 and TASK-006.

**Files:** Create `Scripts/Player/PlayerToolController.cs`; modify `FarmDemo.unity` to attach it to player.

**Responsibilities:** Map 1–4 to tools, locate an `IInteractable` by short camera-forward raycast/overlap, invoke it only in range, and publish selected tool/prompt changes.

**Acceptance Criteria:**

- [ ] key `1` -> selected tool is Hoe; `4` -> Harvest.
- [ ] use key while no plot is targeted -> returns false and no game state changes.
- [ ] use key within range -> calls `TryInteract` once with selected tool.

## TASK-004: Implement farm plot state machine and placeholder visuals

**Phase/Sprint:** 2: Farm one plot

**Input:** TASK-001 scene shell.

**Output:** `FarmPlot.prefab` and validated `FarmPlot`, consumed by TASK-003, TASK-005, TASK-006.

**Files:** Create `Scripts/Farming/FarmPlotState.cs`, `IInteractable.cs`, `FarmPlot.cs`, `Prefabs/FarmPlot.prefab`, and `Tests/EditMode/FarmPlotTests.cs`.

**Responsibilities:** Enforce all state transitions, switch tilled/seed/crop visual children, invoke harvested event exactly once, and expose an inspector-safe test hook only if needed by Unity tests.

**Acceptance Criteria:**

- [ ] `TryInteract(Hoe)` in Untilled -> `Tilled` and returns true.
- [ ] `TryInteract(Seeds)` in Untilled -> returns false and remains Untilled.
- [ ] Hoe, Seeds, WateringCan, growth advance, growth advance, Harvest -> returns to Untilled and emits crop amount `1` once.
- [ ] any incorrect tool/state pair -> returns false with no visual/state mutation.

## TASK-005: Add inventory counter and farming HUD

**Phase/Sprint:** 3: Present and ship

**Input:** Selected tool/prompt from TASK-003 and harvest event from TASK-004.

**Output:** HUD panel and inventory state consumed by TASK-006.

**Files:** Create `Scripts/UI/InventoryState.cs`, `FarmHud.cs`, `Tests/EditMode/InventoryStateTests.cs`; modify `FarmDemo.unity` with Canvas/TextMeshPro labels.

**Responsibilities:** Subscribe/unsubscribe event handlers safely, display selected tool and crop count, and make invalid interaction feedback readable without logging every frame.

**Acceptance Criteria:**

- [ ] `AddCrop(1)` from zero -> HUD displays `Crops: 1`.
- [ ] `AddCrop(0)` -> count remains unchanged.
- [ ] selecting WateringCan -> HUD displays its name and plot prompt when targeted.

## TASK-006: Integrate environment feedback and polish the demo loop

**Phase/Sprint:** 3: Present and ship

**Input:** TASK-002 movement, TASK-004 plot, TASK-005 HUD.

**Output:** A presentable full loop in `FarmDemo`, consumed by TASK-007.

**Files:** Modify `FarmDemo.unity`, `FarmPlot.prefab`, `FarmPlot.cs`; create simple URP materials and optional particle prefab under `Assets/FarmRestoration`.

**Responsibilities:** Place visual boundaries, path/rocks/trees made from primitives, add modest water/dust/harvest particles, and ensure each crop state has clearly distinct color/shape.

**Acceptance Criteria:**

- [ ] all six plot states have visibly distinct feedback.
- [ ] a full loop can be demonstrated in under 60 seconds without Unity Console errors.
- [ ] active object count remains below 100 in play mode.

## TASK-007: Configure Android and verify the build path

**Phase/Sprint:** 3: Present and ship

**Input:** TASK-006 playable scene.

**Output:** Android-ready build settings and test record.

**Files:** Modify `ProjectSettings/EditorBuildSettings.asset`; create `docs/plans/farm-demo/2026-09-18-smoke-test.md`.

**Responsibilities:** Put `FarmDemo` first in Build Settings, switch active profile to Android, use portrait/landscape according to HUD layout (landscape recommended), and perform editor plus device smoke checks.

**Acceptance Criteria:**

- [ ] Build Settings -> first enabled scene is `FarmDemo`.
- [ ] Android build completes without missing SDK/NDK/JDK errors.
- [ ] device/editor run -> movement, interaction, harvest HUD work with no crash.

# 9. Edge Cases

| # | Scenario | Expected Behavior | Handled In |
|---|---|---|---|
| 1 | Wrong tool used on a plot state | No state/visual change; HUD retains a clear prompt | TASK-004, TASK-005 |
| 2 | Use action while outside plot range | No interaction or harvest | TASK-003 |
| 3 | Diagonal movement input | Movement speed is normalized | TASK-002 |
| 4 | Harvest repeatedly in one frame | Only first valid call yields one crop; plot resets | TASK-004 |
| 5 | Inspector reference missing | Component logs setup error once and avoids null crash | TASK-002, TASK-004, TASK-005 |
| 6 | Android SDK components absent | Build verification stops with a direct installation instruction | TASK-007 |

# 11. Verification Plan

**Unit Tests:** `FarmPlotTests` validates valid/invalid transition matrix and one harvest event; `InventoryStateTests` validates positive increments and zero rejection.

**Manual / Smoke Tests:**

- Editor: launch FarmDemo, move to plot, perform all six interactions, verify one crop and reset.
- Android: install build, launch in landscape, execute same loop, inspect Console/logcat only if an error occurs.

**Success Criteria:** All Unity tests pass; no Console errors in the 60-second demo; Android build completes; all acceptance steps in the source spec work.
